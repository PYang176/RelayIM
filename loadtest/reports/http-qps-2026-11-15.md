# HTTP 消息 QPS 容量测试：2026-11-15

## 测试目标

测量当前单机 Docker 环境在真实群消息发送链路中的稳定成功 QPS、接口延迟和限流行为。消息经过 JWT 鉴权、会话成员校验、MySQL 事务、会话序号更新和 Outbox 写入，不是只读接口。

## 环境

| 项目 | 配置 |
| --- | --- |
| 应用 | 单实例 Go 服务 |
| 数据库 | 本机 MySQL 8.0 |
| 基础设施 | Redis、RabbitMQ、SeaweedFS 运行于 Docker Desktop WSL2 |
| 压测工具 | k6 0.57.0 |
| 场景 | 90 人同群，每个 VU 使用独立成员和 Token |
| 消息类型 | 文本消息 |
| 持续时间 | 每组 30 秒 |

## 结果

成功 QPS 取 `iterations` 指标，只有返回 `201` 且包含服务端 `seq` 的请求才通过检查。

| 并发 VU | 请求间隔 | 成功 QPS | P95 | P99 | HTTP 失败 | 429 |
| ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 75 | 0.8 s | 70.19 | 326.22 ms | 756.51 ms | 0% | 0 |
| 90 | 0.8 s | 70.52 | 551.43 ms | 901.31 ms | 0% | 0 |
| 90 | 0.4 s | **81.98** | **803.28 ms** | **956.69 ms** | 0% | 0 |
| 90 | 0.2 s | 81.62 | 1268.72 ms | 1535.12 ms | 0% | 0 |

最终观测到约 **82 条/秒**的成功写入平台。继续压缩请求间隔后，成功 QPS 没有提高，P95 从 803 ms 上升到 1269 ms，说明当前单机应用在处理和 90 人群消息扇出链路附近达到饱和。

## 可靠性观测

压测期间：

- HTTP 5xx 为 0
- 消息请求失败率为 0
- 限流拒绝为 0
- Outbox 待发布事件峰值约 2,552 条
- 压测结束后 Outbox pending 回到 0，dead 为 0

这说明短时写入峰值会先在 Outbox 中形成可控缓冲，后台 Worker 随后完成发布，而不是把消息丢失或静默降级为成功。

## 结论

当前本机单实例环境的安全展示值可写为：

> 90 人同群消息发送场景下，消息 Accepted 峰值约 82 QPS，P95 约 803 ms，P99 约 957 ms，请求失败率和 5xx 均为 0。

常规负载下的低延迟基线仍以 [HTTP 消息基线](./http-baseline.md) 和 [30 分钟长稳报告](./soak-fault-2026-11-12.md) 为准。
