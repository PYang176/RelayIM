## 3. 审查中发现并修复的问题

| 问题 | 处理 |
| --- | --- |
| Go 1.26.10 标准库存在可触达的 `net/http` 漏洞 GO-2026-6859 | 升级到 Go 1.26.11，`govulncheck` 零漏洞 |
| JWT 实现残留固定密钥注释 | 删除硬编码示例，启动时要求密钥至少 32 字节 |
| MySQL 连接池硬编码为 200，可能高于默认 `max_connections` | 改为默认 50，并支持环境变量覆盖和边界归一化 |
| 备注、删除好友的 OpenAPI 状态码与 Handler 不一致 | OpenAPI 修正为实际返回的 `200` |
| 同一发送者并发写入不同会话时，唯一索引检查使用 `FOR UPDATE` 导致 gap lock 死锁 | 移除不必要的锁定，保留唯一索引和 1062 兜底 |
| 多份 E2E 仍引用已删除的旧联系人抽屉和管理入口 | 更新为当前联系人工作区、群成员列表和 rail 导航 |
| WebSocket 压测群成员只收到邀请但没有接受 | 压测准备阶段先接受群邀请，再建立 WebSocket 连接 |

## 4. 异常与边界测试

新增 `scripts/http-boundary-e2e.py`，覆盖：

- 未认证访问返回 `401`。
- 非法、自己和不存在的用户关系状态返回 `400/404`。
- 好友申请理由空白和 201 字符返回 `400`，恰好 200 字符返回 `201`。
- 待处理申请在双方视角的 `requested_by_me` 方向相反。
- 好友备注 64 字符成功，65 字符拒绝。
- 消息正文 8000 字符成功，8001 字符和空白正文拒绝。
- 重复客户端消息 ID 返回同一条服务端消息。
- 分页上限、搜索词为空和搜索词过长均拒绝。
- 拉黑后双方不能继续私聊或申请。
- 单向删除后被删除方可以重新申请。

结果：全部通过。

## 5. HTTP 消息压测

场景：10 个独立发送账号、10 个 VU、持续 30 秒、每轮间隔 0.8 秒。

发送账号独立，避免单用户每 10 秒 20 条的限流影响消息链路容量结果。

| 指标 | 结果 |
| --- | ---: |
| 成功消息 | 370 |
| 业务检查 | 740 / 740 |
| 消息检查成功率 | 100% |
| 消息接口 2xx | 370 |
| 消息接口 4xx/5xx（应用重启后） | 0 / 0 |
| 吞吐 | 12.33 条/秒 |
| 平均延迟 | 27.19 ms |
| P95 | 52.36 ms |
| P99 | 58.84 ms |
| 最大延迟 | 64.81 ms |

压测结束后：

- Outbox `pending=0`、`processing=0`、`dead=0`。
- RabbitMQ `message.created.v1` 消费成功 370 条。
- MySQL 连接池 `open=10`、`in_use=0`、`max=50`。

原始摘要：[audit-http-final-fixed.json](./audit-http-final-fixed.json)

## 6. WebSocket 端到端投递

场景：4 个在线接收端、1 个发送端、持续 20 秒、发送间隔 0.6 秒。

| 指标 | 结果 |
| --- | ---: |
| WebSocket 建连 | 4 / 4，100% |
| 发送消息 | 23 |
| 在线投递次数 | 92 |
| 发送请求检查 | 100% |
| 投递平均延迟 | 290.79 ms |
| 投递 P95 | 500 ms |
| 投递 P99 | 545 ms |
| 最大延迟 | 545 ms |

功能链路全部成功，但严格阈值 `P95 < 500 ms` 因结果恰好等于 500 ms 判定失败。当前 Outbox 默认轮询间隔为 500 ms，端到端 P95 会天然贴近该间隔；若要低于阈值，需要调整 Outbox 轮询频率并重新评估数据库扫描压力，不能仅修改测试阈值。

原始摘要：[audit-websocket-final-v2.json](./audit-websocket-final-v2.json)

## 7. 限流验证

首轮使用同一个发送账号运行 10 VU，业务检查大量返回 `429`。该结果说明单用户滑动窗口限流生效，不应作为消息链路吞吐结果。正式压测改为每个 VU 独立账号，并只对消息发送标签计算失败率。

## 8. 已知限制

- 本轮未执行 30 分钟以上长时间稳定性测试。
- 本轮未执行 RabbitMQ、Redis、MySQL 进程强杀后的故障恢复测试。
- WebSocket P95 处于默认 500 ms 轮询边界，尚未做 Outbox 轮询优化。
- 结果来自单机 Docker 环境，不代表生产集群容量。
