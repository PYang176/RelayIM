# 性能与容量验收

本文汇总 RelayIM 当前已执行的性能、稳定性和故障恢复测试，统一说明测试口径与可对外表述的边界。详细过程与原始数据位于 [压测报告索引](../loadtest/reports/README.md)。

## 1. 结论摘要

| 验收项 | 实测结果 |
| --- | --- |
| HTTP 消息长稳 | 20 个独立发送账号持续 30 分钟，完成 35,140 条，P95 41.91 ms，P99 55.27 ms |
| HTTP 消息短时容量 | 40 个独立发送账号持续 2 分钟，完成 4,680 条，约 39 条/秒，P95 46.80 ms |
| 普通群消息在线投递 | 20 个在线接收端，114 条消息产生 2,280 次投递，P95 482 ms，P99 500 ms |
| 空闲 WebSocket 连接 | 5,000 个连接完整重叠，建连成功率 99.90%，握手 P95 6.22 ms |
| 300 人同群瞬时发送 | 300 条消息全部 Accepted，300 个在线连接完整收到 90,000 次投递，端到端 P99 6.66 秒 |
| RabbitMQ 中断与恢复 | 中断期间消息保存在 Outbox，恢复约 12.42 秒后主队列清零，无新增死信 |
| Redis 中断与恢复 | 依赖 Redis 的请求返回 503，恢复约 11.45 秒后重新登录和发送成功 |
| MySQL 中断与恢复（历史容器测试） | 写请求失败且就绪检查返回 503，恢复约 11.36 秒后发送成功 |

测试完成后，长稳和大群场景的 Outbox 均为 `pending=0`、`processing=0`、`dead=0`。5,000 连接关闭后，WebSocket 连接能够回落到 0；30 分钟长稳结束后，MySQL 连接池回落到 10 个打开连接。

## 2. 测试口径

### 2.1 正常业务基线

长稳和小并发测试使用不同发送账号和不同私聊会话，主要观察正常消息写入、Outbox 发布和 Consumer 处理能力。

- 30 分钟长稳验证持续运行和资源稳定性。
- 40 VU 容量场景验证短时并发消息写入。
- 普通 WebSocket 场景验证少量在线接收者的实时扇出。

### 2.2 大群瞬时突发

300 人场景要求所有成员处于同一群、同时在线，并在统一时刻各发送一条消息。每条消息需要向 300 个在线连接投递，因此总共产生 90,000 次 WebSocket 帧入队。

该场景验证的是瞬时突发承接能力，不验证 300 条/秒持续吞吐。

### 2.3 连接容量

5,000 连接测试只建立并保持空闲 WebSocket，不发送业务消息，用于区分“连接容量”和“活跃消息扇出容量”。

### 2.4 故障恢复

故障注入分别停止 RabbitMQ、Redis 和 MySQL，记录故障期间响应、Outbox 状态和恢复时间。MySQL 结果来自早期容器化测试；当前部署已把 MySQL 移到宿主机，自动化故障脚本只管理 RabbitMQ 和 Redis，MySQL 故障需要手动停止本机服务验证。

## 3. 如何解读延迟

| 指标 | 含义 |
| --- | --- |
| HTTP Accepted | 服务端完成消息、会话序号和 Outbox 事务并返回 201 的时间 |
| WebSocket 端到端 | 从客户端发出 HTTP 消息到收到在线 WebSocket 消息的完整时间 |
| 消费者排队延迟 | 领域事件产生到 Consumer 开始处理之间的时间 |
| 连接握手延迟 | 申请 Ticket 后完成 WebSocket 协议升级的时间 |

300 人场景的 P99 6.66 秒包含三部分：300 个请求在同一个群上串行分配 `seq`、Outbox 发布、90,000 次在线扇出。该延迟不适合直接与普通私聊或小群延迟比较。

## 4. 可对外表述

可以写：

- 单实例、5,000 个空闲 WebSocket 同时在线并保持完整重叠。
- 20 个消息发送会话持续运行 30 分钟，完成 35,140 条消息且发送失败为 0。
- 40 个消息发送会话短时达到约 39 条/秒。
- 300 人群成员同秒各发一条时，300 条消息全部持久化，在线覆盖率 100%。
- RabbitMQ、Redis 和 MySQL 中断后均能自动恢复，Outbox 未产生死信。

不能写：

- 已支持 5,000 个活跃发送用户同时聊天。
- 已支持 300 条/秒持续消息吞吐。
- 大群瞬时 P99 6.66 秒等同于普通聊天延迟。
- 单机 Docker 数据等于生产集群上限。

## 5. 已知限制

- 应用、数据库、消息队列和压测客户端运行在同一台开发机上，CPU、磁盘和网络会相互影响。
- 5,000 连接场景只保持约 20 秒，短于一次完整的 25 秒 Ping 周期。
- 长稳场景没有同时保持 5,000 个活跃 WebSocket 收发消息。
- 300 人测试没有覆盖 500 人满群，也没有覆盖 300 人持续每秒发送。
- 故障注入为单节点本地环境，没有覆盖网络分区、磁盘损坏和多副本切换。
