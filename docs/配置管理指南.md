# RelayIM 配置管理指南

本文说明应用配置、环境变量和 Docker Compose 配置的职责边界。

## 1. 配置文件分工

| 文件 | 是否提交 | 用途 |
| --- | --- | --- |
| `internal/config/app.example.yml` | 是 | 应用配置模板，只包含非敏感默认值 |
| `internal/config/app.yml` | 否 | 本地实际应用配置 |
| `internal/config/app.env.example` | 是 | 应用环境变量模板 |
| `internal/config/app.env` | 否 | 本地应用密码和密钥 |
| `deploy/.env.example` | 是 | Compose 基础设施变量模板 |
| `deploy/.env` | 否 | 本地 Compose 实际变量 |
| `deploy/app.env.example` | 是 | 应用容器变量模板 |
| `deploy/app.env` | 否 | 本地应用容器密码和密钥 |

`deploy/.env` 只用于 Docker Compose 变量替换，不会自动注入 Windows 上直接运行的 Go 进程。

## 2. 应用配置优先级

配置加载顺序从低到高：

```text
代码默认值
→ internal/config/app.yml
→ RELAYIM_* 环境变量
```

环境变量优先级高于 YAML，适合保存密码、部署地址和环境差异。

## 3. 首次配置

从模板创建本地配置：

```powershell
Copy-Item internal\config\app.example.yml internal\config\app.yml
```

`app.yml` 已被 `.gitignore` 忽略，不能提交。

非敏感默认值可以保留在 YAML：

```yaml
mysql:
  host: 127.0.0.1
  port: 3306
  user: root
  dbname: relayim
  config:
    charset: utf8mb4
    parseTime: true
    loc: UTC
  pool:
    max_open: 50
    max_idle: 10
    conn_max_lifetime_minutes: 30

jwt:
  expire_hours: 24

redis:
  host: 127.0.0.1
  port: 6379
  db: 0
  dial_timeout_seconds: 3
  read_timeout_seconds: 2
  write_timeout_seconds: 2
  pool_timeout_seconds: 3
  max_retries: 1

rabbitmq:
  url: ""
  publish_timeout_seconds: 5
  poll_interval_ms: 500
  batch_size: 100
  max_publish_attempts: 10
  retry_base_seconds: 2
  claim_lease_seconds: 30
  prefetch: 20
  consumer_workers: 4

s3:
  endpoint: 127.0.0.1:8333
  public_endpoint: ""
  access_key: ""
  secret_key: ""
  bucket: relayim-media
  region: us-east-1
  use_ssl: false

snowflake:
  workID: 1

rate_limit:
  ws_ticket_global: 500
  ws_ticket_user: 10
  ws_ticket_window_ms: 1000
  message_send_user: 20
  message_send_global: 1000
  message_send_window_ms: 10000

tracing:
  enabled: true
  service_name: relayim
  otlp_endpoint: http://127.0.0.1:4318
  sample_ratio: 1.0

attachment_cleanup:
  enabled: true
  interval_seconds: 3600
  pending_ttl_hours: 24
  claim_lease_seconds: 600
  batch_size: 100
```

密码、签名密钥和对象存储凭据通过环境变量注入。

复制环境变量模板：

```powershell
Copy-Item internal\config\app.env.example internal\config\app.env
```

在 `app.env` 中填写实际值。该文件已被 Git 忽略。

## 4. 推荐的本地启动方式

使用启动脚本：

```powershell
.\scripts\run-server.ps1
```

脚本只把 `app.env` 中的变量注入即将运行的 Go 子进程，不会修改当前 PowerShell 会话，也不会打印变量值。

如果 PowerShell 执行策略阻止脚本：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\run-server.ps1
```

## 5. 手动注入环境变量

当前 PowerShell 会话设置：

```powershell
$env:RELAYIM_MYSQL_PASSWORD = "本地数据库密码"
$env:RELAYIM_JWT_SECRET = "本地开发签名密钥"
$env:RELAYIM_REDIS_PASSWORD = "本地 Redis 密码"
$env:RELAYIM_RABBITMQ_URL = "amqp://用户:密码@127.0.0.1:5672/relayim"
$env:RELAYIM_S3_ENDPOINT = "127.0.0.1:8333"
$env:RELAYIM_S3_PUBLIC_ENDPOINT = ""
$env:RELAYIM_S3_ACCESS_KEY = "SeaweedFS 访问密钥"
$env:RELAYIM_S3_SECRET_KEY = "SeaweedFS 秘密"
$env:RELAYIM_S3_BUCKET = "relayim-media"
$env:RELAYIM_S3_REGION = "us-east-1"
$env:RELAYIM_S3_USE_SSL = "false"
$env:RELAYIM_TRACING_ENABLED = "true"
$env:RELAYIM_TRACING_OTLP_ENDPOINT = "http://127.0.0.1:4318"
$env:RELAYIM_ATTACHMENT_CLEANUP_ENABLED = "true"
```

然后从项目根目录启动：

```powershell
go run ./cmd/server
```

这些变量只在当前终端会话中有效，关闭终端后失效。

## 6. 指定配置文件

默认读取：

```text
./internal/config/app.yml
```

也可以通过环境变量指定其他文件：

```powershell
$env:RELAYIM_CONFIG_FILE = "E:\configs\relayim\app.yml"
go run ./cmd/server
```

指定文件必须存在，否则启动失败。

## 8. Docker Compose 配置

只启动基础设施：

```powershell
docker compose --env-file deploy\.env -f deploy\docker-compose.yml up -d
```

`deploy/.env` 用于：

```text
RabbitMQ 用户、密码和 VHost
Redis 密码和宿主机端口（默认 6380）
SeaweedFS 凭据
Grafana 管理密码
Prometheus 保留时间
```

`deploy/.env` 中的 `MINIO_ROOT_USER` 和 `MINIO_ROOT_PASSWORD` 是 SeaweedFS 容器凭据。Windows 上直接运行的 Go 进程必须通过 `internal/config/app.env` 注入对应的 `RELAYIM_S3_ACCESS_KEY` 和 `RELAYIM_S3_SECRET_KEY`。

容器化应用启动使用独立的应用变量文件。MySQL 始终运行在宿主机，应用容器通过 `host.docker.internal` 访问它：

```powershell
Copy-Item deploy\app.env.example deploy\app.env
docker compose `
  --env-file deploy\.env `
  --env-file deploy\app.env `
  -f deploy\docker-compose.yml `
  -f deploy\docker-compose.app.yml `
  up -d --build --remove-orphans
```

`deploy/.env` 继续保存容器基础设施凭据，`deploy/app.env` 保存本机 MySQL、JWT、预签名公开地址和应用开关。Go 容器通过 `host.docker.internal` 连接 MySQL，通过服务名连接 `redis`、`rabbitmq`、`seaweedfs` 和 `tempo`。宿主机上的 Go 进程连接 Docker Redis 时使用 `6380`。

SeaweedFS 同时存在两个地址：

- `RELAYIM_S3_ENDPOINT=seaweedfs:8333` 供 Go 容器上传、读取和删除对象。
- `RELAYIM_S3_PUBLIC_ENDPOINT=http://localhost:8333` 供浏览器直接访问预签名附件地址。

两个地址不能混用。预签名 URL 的签名包含 Host，直接用内部地址生成后替换域名会导致签名失效。

## 9. 为什么同时使用 YAML 和环境变量

YAML 适合：

- 层级结构清晰。
- 保存非敏感默认值。
- 本地直接阅读和修改。

环境变量适合：

- 密码和签名密钥。
- 本地、测试、生产之间的差异。
- Docker 和 CI 部署。
- 同一份代码连接不同基础设施。

## 10. 安全规则

- `app.yml`、`app.env`、`deploy/.env` 和任何真实密钥文件不得提交 Git。
- 日志中不得打印完整 DSN、密码、JWT Secret、对象存储密钥或预签名附件 URL。
- 多实例部署必须为每个实例设置不同的 `RELAYIM_SNOWFLAKE_WORK_ID`。
- 应用启动时会比较当前时钟与数据库最大 Snowflake ID 时间；回拨不超过 5 秒会等待，超过 5 秒会拒绝启动。处理方式见 [雪花 ID 与时钟回拨](./雪花ID与时钟回拨.md)。
- `RELAYIM_MYSQL_LOCATION` 建议统一为 `UTC`。
- 修改密钥后应重启 Go 应用，因为环境变量只在进程启动时读取。

## 11. 配置与代码常量的边界

会随部署环境、凭据、容量和安全策略变化的值应进入 YAML 或 `RELAYIM_*` 环境变量，包括：

- MySQL、Redis、RabbitMQ、SeaweedFS 和 Trace 的地址与凭据。
- HTTP 监听地址、数据库连接池、Snowflake Worker ID 和对象存储公开地址。
- Outbox 发布频率、Consumer 数量与 Prefetch、附件清理参数和写接口限流。
- JWT 密钥及有效期、Trace 采样和清理任务开关。

以下值属于当前产品的固定约束，仍保留在代码常量中。修改它们会改变接口语义或数据边界，因此不能只改部署环境：

- 消息正文最多 8,000 个字符，附件最大 25 MB。
- 单群最多 500 人，群邀请默认 7 天过期。
- 好友备注、申请理由、群名称等字段长度。
- 普通成员和管理员的消息撤回时间窗。
- 注册、登录、好友申请等接口的具体限流策略。

消息发送和 WebSocket Ticket 配额会随实例资源与在线人数变化，已配置化。调整后必须重新执行大群容量测试，不能仅在部署文件中无限放大。
