# GinChat 配置管理指南

本文说明应用配置、环境变量和 Docker Compose 配置的职责边界。

## 1. 配置文件分工

| 文件 | 是否提交 | 用途 |
| --- | --- | --- |
| `internal/config/app.example.yml` | 是 | 应用配置模板，只包含非敏感默认值 |
| `internal/config/app.yml` | 否 | 本地实际应用配置 |
| `internal/config/app.env.example` | 是 | 应用环境变量模板 |
| `internal/config/app.env` | 否 | 本地应用密码和密钥 |
| `deploy/.env.example` | 是 | Compose 基础设施变量模板 |
| `deploy/.env` | 否 | 本地 Compose 实际变量 |

`deploy/.env` 只用于 Docker Compose 变量替换，不会自动注入 Windows 上直接运行的 Go 进程。

## 2. 应用配置优先级

配置加载顺序从低到高：

```text
代码默认值
→ internal/config/app.yml
→ GINCHAT_* 环境变量
```

环境变量优先级高于 YAML，适合保存密码、部署地址和环境差异。

## 3. 首次配置

从模板创建本地配置：

```powershell
Copy-Item internal\config\app.example.yml internal\config\app.yml
```

`app.yml` 已被 `.gitignore` 忽略，不能提交。

非敏感默认值可以保留在 YAML：

```yaml
mysql:
  host: 127.0.0.1
  port: 3306
  user: root
  dbname: ginchat_v2
  config:
    charset: utf8mb4
    parseTime: true
    loc: UTC

jwt:
  expire_hours: 24

redis:
  host: 127.0.0.1
  port: 6379
  db: 0

rabbitmq:
  url: ""
  publish_timeout_seconds: 5
  poll_interval_ms: 500
  batch_size: 100
  max_publish_attempts: 10
  retry_base_seconds: 2
  claim_lease_seconds: 30
  prefetch: 20

s3:
  endpoint: 127.0.0.1:8333
  access_key: ""
  secret_key: ""
  bucket: ginchat-media
  region: us-east-1
  use_ssl: false

snowflake:
  workID: 1
```

密码、签名密钥和对象存储凭据通过环境变量注入。

复制环境变量模板：

```powershell
Copy-Item internal\config\app.env.example internal\config\app.env
```

在 `app.env` 中填写实际值。该文件已被 Git 忽略。

## 4. 推荐的本地启动方式

使用启动脚本：

```powershell
.\scripts\run-server.ps1
```

脚本只把 `app.env` 中的变量注入即将运行的 Go 子进程，不会修改当前 PowerShell 会话，也不会打印变量值。

如果 PowerShell 执行策略阻止脚本：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\run-server.ps1
```

## 5. 手动注入环境变量

当前 PowerShell 会话设置：

```powershell
$env:GINCHAT_MYSQL_PASSWORD = "本地数据库密码"
$env:GINCHAT_JWT_SECRET = "本地开发签名密钥"
$env:GINCHAT_REDIS_PASSWORD = "本地 Redis 密码"
$env:GINCHAT_RABBITMQ_URL = "amqp://用户:密码@127.0.0.1:5672/ginchat"
$env:GINCHAT_S3_ENDPOINT = "127.0.0.1:8333"
$env:GINCHAT_S3_ACCESS_KEY = "SeaweedFS 访问密钥"
$env:GINCHAT_S3_SECRET_KEY = "SeaweedFS 秘密"
$env:GINCHAT_S3_BUCKET = "ginchat-media"
$env:GINCHAT_S3_REGION = "us-east-1"
$env:GINCHAT_S3_USE_SSL = "false"
```

然后从项目根目录启动：

```powershell
go run ./cmd/server
```

这些变量只在当前终端会话中有效，关闭终端后失效。

## 6. 指定配置文件

默认读取：

```text
./internal/config/app.yml
```

也可以通过环境变量指定其他文件：

```powershell
$env:GINCHAT_CONFIG_FILE = "E:\configs\ginchat\app.yml"
go run ./cmd/server
```

指定文件必须存在，否则启动失败。

## 7. 环境变量清单

| 环境变量 | 对应 YAML | 说明 |
| --- | --- | --- |
| `GINCHAT_CONFIG_FILE` | 无 | 覆盖配置文件路径 |
| `GINCHAT_SERVER_ADDR` | 无 | HTTP 监听地址，默认 `:8081` |
| `GINCHAT_MYSQL_HOST` | `mysql.host` | MySQL 地址 |
| `GINCHAT_MYSQL_PORT` | `mysql.port` | MySQL 端口 |
| `GINCHAT_MYSQL_USER` | `mysql.user` | MySQL 用户 |
| `GINCHAT_MYSQL_PASSWORD` | `mysql.password` | MySQL 密码 |
| `GINCHAT_MYSQL_DBNAME` | `mysql.dbname` | 数据库名 |
| `GINCHAT_MYSQL_CHARSET` | `mysql.config.charset` | 字符集 |
| `GINCHAT_MYSQL_PARSE_TIME` | `mysql.config.parseTime` | 是否解析时间 |
| `GINCHAT_MYSQL_LOCATION` | `mysql.config.loc` | 时区名称 |
| `GINCHAT_JWT_SECRET` | `jwt.secret` | JWT 密钥 |
| `GINCHAT_JWT_EXPIRE_HOURS` | `jwt.expire_hours` | Token 有效小时数 |
| `GINCHAT_JWT_REFRESH_EXPIRE_DAYS` | `jwt.refresh_expire_days` | Refresh Token 有效天数，默认 30 |
| `GINCHAT_REDIS_HOST` | `redis.host` | Redis 地址 |
| `GINCHAT_REDIS_PORT` | `redis.port` | Redis 端口 |
| `GINCHAT_REDIS_PASSWORD` | `redis.password` | Redis 密码 |
| `GINCHAT_REDIS_DB` | `redis.db` | Redis DB |
| `GINCHAT_RABBITMQ_URL` | `rabbitmq.url` | 完整 AMQP 地址；为空时禁用 RabbitMQ 后台任务 |
| `GINCHAT_RABBITMQ_PUBLISH_TIMEOUT_SECONDS` | `rabbitmq.publish_timeout_seconds` | 单条消息等待 Publisher Confirm 的秒数 |
| `GINCHAT_RABBITMQ_POLL_INTERVAL_MS` | `rabbitmq.poll_interval_ms` | Outbox 空闲扫描间隔 |
| `GINCHAT_RABBITMQ_BATCH_SIZE` | `rabbitmq.batch_size` | 单次领取的 Outbox 事件数量 |
| `GINCHAT_RABBITMQ_MAX_PUBLISH_ATTEMPTS` | `rabbitmq.max_publish_attempts` | 最大发布尝试次数 |
| `GINCHAT_RABBITMQ_RETRY_BASE_SECONDS` | `rabbitmq.retry_base_seconds` | 指数退避初始秒数 |
| `GINCHAT_RABBITMQ_CLAIM_LEASE_SECONDS` | `rabbitmq.claim_lease_seconds` | Outbox 处理租约秒数 |
| `GINCHAT_RABBITMQ_PREFETCH` | `rabbitmq.prefetch` | Consumer 最大未 ACK 消息数量 |
| `GINCHAT_S3_ENDPOINT` | `s3.endpoint` | SeaweedFS S3 API 的 `host:port` |
| `GINCHAT_S3_ACCESS_KEY` | `s3.access_key` | 对象存储访问密钥；为空时禁用附件上传 |
| `GINCHAT_S3_SECRET_KEY` | `s3.secret_key` | 对象存储秘密；为空时禁用附件上传 |
| `GINCHAT_S3_BUCKET` | `s3.bucket` | 聊天附件 Bucket，默认 `ginchat-media` |
| `GINCHAT_S3_REGION` | `s3.region` | S3 签名区域，本地默认 `us-east-1` |
| `GINCHAT_S3_USE_SSL` | `s3.use_ssl` | 是否使用 HTTPS 连接对象存储 |
| `GINCHAT_WS_TICKET_RATE_LIMIT_GLOBAL` | `rate_limit.ws_ticket_global` | 全实例滑动窗口 Ticket 上限，默认 250 |
| `GINCHAT_WS_TICKET_RATE_LIMIT_USER` | `rate_limit.ws_ticket_user` | 单用户滑动窗口 Ticket 上限，默认 10 |
| `GINCHAT_WS_TICKET_RATE_LIMIT_WINDOW_MS` | `rate_limit.ws_ticket_window_ms` | Ticket 滑动窗口毫秒数，默认 1000 |
| `GINCHAT_SNOWFLAKE_WORK_ID` | `snowflake.workID` | 实例唯一 Worker ID |

## 8. Docker Compose 配置

Compose 配置只负责容器：

```powershell
docker compose --env-file deploy\.env -f deploy\docker-compose.yml up -d
```

`deploy/.env` 当前用于：

```text
RabbitMQ 用户、密码和 VHost
Redis 密码
SeaweedFS 凭据
Grafana 管理密码
Prometheus 保留时间
```

`deploy/.env` 中的 `MINIO_ROOT_USER` 和 `MINIO_ROOT_PASSWORD` 是 SeaweedFS 容器凭据。Windows 上直接运行的 Go 进程必须通过 `internal/config/app.env` 注入对应的 `GINCHAT_S3_ACCESS_KEY` 和 `GINCHAT_S3_SECRET_KEY`。

不要在其中混入 `GINCHAT_*` 应用配置。未来 Go 应用进入容器后，再由 Compose 的 `environment` 或独立 `env_file` 显式注入应用变量。

## 9. 为什么同时使用 YAML 和环境变量

YAML 适合：

- 层级结构清晰。
- 保存非敏感默认值。
- 本地直接阅读和修改。

环境变量适合：

- 密码和签名密钥。
- 本地、测试、生产之间的差异。
- Docker 和 CI 部署。
- 同一份代码连接不同基础设施。

## 10. 安全规则

- `app.yml`、`app.env`、`deploy/.env` 和任何真实密钥文件不得提交 Git。
- 日志中不得打印完整 DSN、密码、JWT Secret、对象存储密钥或预签名附件 URL。
- 多实例部署必须为每个实例设置不同的 `GINCHAT_SNOWFLAKE_WORK_ID`。
- `GINCHAT_MYSQL_LOCATION` 建议统一为 `UTC`。
- 修改密钥后应重启 Go 应用，因为环境变量只在进程启动时读取。
