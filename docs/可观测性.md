# 可观测性

本文说明 GinChat 当前的健康检查、请求追踪、结构化日志、Prometheus 指标和 Grafana 面板。

## 1. 健康检查

### 存活检查

```http
GET /health/live
```

```json
{
  "status": "alive"
}
```

存活检查只表示 Go 进程仍能处理 HTTP 请求，不访问外部依赖。适用于判断进程是否需要重启。

### 就绪检查

```http
GET /health/ready
```

正常响应：

```json
{
  "status": "ready",
  "checks": {
    "mysql": "up",
    "redis": "up"
  }
}
```

任一启动必需依赖不可用时返回 `503 Service Unavailable`，`status` 为 `not_ready`，故障依赖标记为 `down`。

当前就绪检查覆盖：

- MySQL：使用连接池 `PingContext`。
- Redis：用于认证、WebSocket Ticket 和心跳。

SeaweedFS 是可选附件依赖，未配置凭据时文本和会话功能仍可使用；RabbitMQ 由 Outbox 支持恢复，因此二者不直接阻止服务就绪。

## 2. Request ID

每个 HTTP 请求都会返回 `X-Request-ID`：

- 客户端提供 8 至 128 位安全字符时沿用该 ID。
- 缺失或格式不安全时服务端生成 128 位随机十六进制 ID。
- ID 同时写入请求 Context 和访问日志。
- 不记录查询字符串，因此不会把 WebSocket Ticket、Token 或预签名 URL 写入访问日志。

后续业务日志可以通过 `middleware.RequestIDFromContext(ctx)` 获取追踪 ID。

## 3. 结构化日志

服务默认使用 `log/slog` JSON Handler。访问日志示例：

```json
{
  "time": "2026-11-08T12:22:01.84+08:00",
  "level": "INFO",
  "msg": "HTTP 请求完成",
  "request_id": "a1702a9144e324449e085824ffb6e48b",
  "method": "GET",
  "route": "/api/v1/conversations",
  "status": 200,
  "duration_ms": 8
}
```

`/metrics`、健康检查和 `/ws` 不写访问日志，避免高频抓取和 Ticket 泄露。WebSocket 业务错误、RabbitMQ 重连、Outbox 死信和数据库异常使用结构化日志字段。

## 4. Prometheus 指标

```http
GET /metrics
```

主要指标：

| 指标 | 类型 | 说明 |
| --- | --- | --- |
| `ginchat_http_requests_total` | Counter | 按方法、路由和状态类别统计请求 |
| `ginchat_http_request_duration_seconds` | Histogram | HTTP 请求耗时 |
| `ginchat_http_requests_in_flight` | Gauge | 当前正在处理的请求数 |
| `ginchat_websocket_connections` | Gauge | 当前进程内有效 WebSocket 连接数 |
| `ginchat_db_connections` | Gauge | MySQL 连接池 `open/in_use/idle/max` |
| `ginchat_message_accepted_total` | Counter | 按文本、图片、文件和是否重复统计服务端已接受消息 |
| `ginchat_attachment_uploads_total` | Counter | 附件上传成功与失败次数 |
| `ginchat_outbox_events` | Gauge | Outbox `pending/processing/published/dead` 状态数量 |
| `ginchat_outbox_query_success` | Gauge | 最近一次 Outbox 指标查询是否成功 |
| `go_goroutines` | Gauge | Go 协程数量 |
| `go_memstats_heap_alloc_bytes` | Gauge | 当前堆内存 |

HTTP 指标使用路由模板而不是真实 URL，避免把消息 ID、会话 ID 等高基数 Snowflake 写入 Prometheus Label。

## 5. Prometheus 与 Grafana

Prometheus 抓取地址：

```text
host.docker.internal:8081/metrics
```

Grafana：

```text
http://127.0.0.1:3000
```

面板自动加载为 `GinChat Overview`，包含：

- HTTP 请求速率。
- 各路由 P95 延迟。
- HTTP 5xx 错误率。
- 处理中请求和 WebSocket 连接数。
- MySQL 连接池。
- Goroutine 与堆内存。
- 文本、图片和文件消息接受速率。
- Outbox 各状态数量。
- 附件上传成功率。

验证 Prometheus 目标：

```powershell
(Invoke-RestMethod 'http://127.0.0.1:9090/api/v1/targets').data.activeTargets |
    Where-Object { $_.labels.job -eq 'ginchat-app' } |
    Select-Object health,lastError,scrapeUrl
```

## 6. 当前限制

- Request ID 暂未写入 Outbox 事件和 RabbitMQ 消息头，因此还不能形成跨 HTTP、消息队列和 WebSocket 的完整 Trace。
- 当前没有 OpenTelemetry 分布式追踪。
- 消息 Accepted、附件上传和 Outbox 积压已覆盖；消息消费失败率、端到端投递延迟和 DLQ 增量仍待增加。
- 多实例运行时 Grafana 会把各实例连接数直接相加，Presence 和跨实例路由仍待实现。
- `internal/consumer`、`internal/api` 等未进入主 Router 的旧版原型代码仍有历史调试输出，不属于当前运行时链路。
