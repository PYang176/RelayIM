# 可观测性

本文说明 RelayIM 当前的健康检查、请求追踪、OpenTelemetry Trace、结构化日志、Prometheus 指标和 Grafana 面板。

## 1. 健康检查

### 存活检查

```http
GET /health/live
```

```json
{
  "status": "alive"
}
```

存活检查只表示 Go 进程仍能处理 HTTP 请求，不访问外部依赖。适用于判断进程是否需要重启。

### 就绪检查

```http
GET /health/ready
```

正常响应：

```json
{
  "status": "ready",
  "checks": {
    "mysql": "up",
    "redis": "up"
  }
}
```

任一启动必需依赖不可用时返回 `503 Service Unavailable`，`status` 为 `not_ready`，故障依赖标记为 `down`。

当前就绪检查覆盖：

- MySQL：使用连接池 `PingContext`。
- Redis：用于认证、WebSocket Ticket 和心跳。

SeaweedFS 是可选附件依赖，未配置凭据时文本和会话功能仍可使用；RabbitMQ 由 Outbox 支持恢复，因此二者不直接阻止服务就绪。

## 2. Request ID

每个 HTTP 请求都会返回 `X-Request-ID`：

- 客户端提供 8 至 128 位安全字符时沿用该 ID。
- 缺失或格式不安全时服务端生成 128 位随机十六进制 ID。
- ID 同时写入请求 Context 和访问日志。
- 不记录查询字符串，因此不会把 WebSocket Ticket、Token 或预签名 URL 写入访问日志。

启用 Trace 后还会返回 `X-Trace-ID`。Request ID 用于关联本服务日志，Trace ID 用于关联 HTTP、Outbox、RabbitMQ 和 WebSocket 链路。

## 3. OpenTelemetry Trace

Go 服务通过 OpenTelemetry SDK 创建 Span，使用 OTLP HTTP 导出到 Grafana Tempo。Grafana 已配置 Tempo 数据源。

核心消息 Trace 包含：

```text
HTTP POST /messages（Server）
  -> outbox.publish（Producer）
  -> rabbitmq.consume（Consumer）
  -> realtime.route（Producer）
  -> rabbitmq.consume ws.delivery（Consumer）
```

跨异步边界使用 W3C `traceparent`：

1. HTTP Handler 创建根 Span。
2. 业务事务把当前 `traceparent` 写入 `outbox_events.trace_parent`。
3. Outbox Worker 恢复父上下文，创建 Producer Span。
4. RabbitMQ Publisher 把传播头写入消息 Header。
5. Consumer 从 Header 恢复同一个 Trace。
6. WebSocket JSON 帧携带非敏感 `trace_id`，便于前后端事件关联。

Trace 不记录 JWT、消息正文、附件内容和用户隐私字段。采样比例由 `RELAYIM_TRACING_SAMPLE_RATIO` 配置，本地默认全量采样。

查看地址：

```text
Tempo HTTP API: http://127.0.0.1:3200
Grafana:        http://127.0.0.1:3000
```

## 4. 结构化日志

服务默认使用 `log/slog` JSON Handler。访问日志示例：

```json
{
  "time": "2026-11-08T12:22:01.84+08:00",
  "level": "INFO",
  "msg": "HTTP 请求完成",
  "request_id": "a1702a9144e324449e085824ffb6e48b",
  "method": "GET",
  "route": "/api/v1/conversations",
  "status": 200,
  "duration_ms": 8
}
```

`/metrics`、健康检查和 `/ws` 不写访问日志，避免高频抓取和 Ticket 泄露。WebSocket 业务错误、RabbitMQ 重连、Outbox 死信和数据库异常使用结构化日志字段。

## 5. Prometheus 指标

```http
GET /metrics
```

主要指标：

| 指标 | 类型 | 说明 |
| --- | --- | --- |
| `relayim_http_requests_total` | Counter | 按方法、路由和状态类别统计请求 |
| `relayim_http_request_duration_seconds` | Histogram | HTTP 请求耗时 |
| `relayim_http_requests_in_flight` | Gauge | 当前正在处理的请求数 |
| `relayim_websocket_connections` | Gauge | 当前进程内有效 WebSocket 连接数 |
| `relayim_db_connections` | Gauge | MySQL 连接池 `open/in_use/idle/max` |
| `relayim_message_accepted_total` | Counter | 按文本、图片、文件和是否重复统计服务端已接受消息 |
| `relayim_attachment_uploads_total` | Counter | 附件上传成功与失败次数 |
| `relayim_attachment_cleanup_total` | Counter | 孤儿附件清理成功与失败次数 |
| `relayim_attachment_orphans` | Gauge | 当前满足清理条件的孤儿附件数量 |
| `relayim_rate_limit_rejected_total` | Counter | 按 `user/ip/global` 范围统计被限流拒绝的请求 |
| `relayim_message_consumer_events_total` | Counter | 按事件类型和 `success/retry/dead` 结果统计消费投递 |
| `relayim_message_consumer_duration_seconds` | Histogram | 消费者处理单条事件的耗时 |
| `relayim_message_consumer_lag_seconds` | Histogram | 事件发生到消费者开始处理的端到端排队延迟 |
| `relayim_outbox_events` | Gauge | Outbox `pending/processing/published/dead` 状态数量 |
| `relayim_outbox_query_success` | Gauge | 最近一次 Outbox 指标查询是否成功 |
| `go_goroutines` | Gauge | Go 协程数量 |
| `go_memstats_heap_alloc_bytes` | Gauge | 当前堆内存 |

HTTP 指标使用路由模板而不是真实 URL，避免把消息 ID、会话 ID 等高基数 Snowflake 写入 Prometheus Label。

## 6. Prometheus 与 Grafana

Prometheus 抓取地址：

```text
host.docker.internal:8081/metrics
```

Grafana：

```text
http://127.0.0.1:3000
```

面板自动加载为 `RelayIM Overview`，包含：

- HTTP 请求速率。
- 各路由 P95 延迟。
- HTTP 5xx 错误率。
- 处理中请求和 WebSocket 连接数。
- MySQL 连接池。
- Goroutine 与堆内存。
- 文本、图片和文件消息接受速率。
- Outbox 各状态数量。
- 附件上传成功率。
- 接口与 Ticket 限流拒绝速率。
- 消息消费者成功率、重试率和死信率。
- 消费者处理 P95 与事件排队 P95。

验证 Prometheus 目标：

```powershell
(Invoke-RestMethod 'http://127.0.0.1:9090/api/v1/targets').data.activeTargets |
    Where-Object { $_.labels.job -eq 'relayim-app' } |
    Select-Object health,lastError,scrapeUrl
```

## 7. 当前限制

- Trace 当前覆盖服务端 HTTP、Outbox、RabbitMQ 和实时路由，尚未覆盖浏览器客户端操作和每一条 SQL Span。
- Tempo 使用单机本地存储，适合当前开发环境，不是生产级对象存储后端。
- 尚未配置 Alertmanager 告警规则、Trace 到日志的自动跳转和长期指标存储。
- Grafana 会把多实例连接数直接相加；跨实例投递已可查 Trace，但容量和故障恢复仍需持续压测。
