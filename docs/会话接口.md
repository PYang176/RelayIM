# 会话接口

所有接口都要求 `Authorization: Bearer <JWT>`，当前用户只能从认证上下文读取，不能由请求体伪造。

## 1. 创建或获取私聊

```http
POST /api/v1/conversations/private
Content-Type: application/json
```

```json
{
  "peer_user_id": "1839281749283749120"
}
```

- 首次创建返回 `201 Created`。
- 相同两个用户再次请求时返回已有会话和 `200 OK`。
- 私聊由较小的用户 ID 和较大的用户 ID 唯一确定，数据库唯一索引负责处理并发创建。
- 不能与自己创建私聊；用户不存在时返回 `404 Not Found`。

## 2. 创建群聊

```http
POST /api/v1/conversations/groups
Content-Type: application/json
```

```json
{
  "name": "后端学习群",
  "avatar_url": "",
  "member_user_ids": [
    "1839281749283749121",
    "1839281749283749122"
  ],
  "invite_remark": "邀请参与后端学习小组的每周讨论"
}
```

- 群名称去除首尾空格后不能为空，最多 64 个 Unicode 字符。
- `member_user_ids` 至少包含一位好友，最多邀请 499 人；连同群主后单群上限 500 人。
- 受邀用户必须仍是群主的有效好友，后端会再次校验，不能只依赖前端选择列表。
- `invite_remark` 必填，去除首尾空白后最多 200 字，被邀请人和群管理员都能查看。
- 创建会话、加入群主和生成好友邀请在同一事务中完成；受邀用户同意前不会进入群。
- 成功返回 `201 Created`，响应中的 `member_count` 为 1，只包含群主。
- 建群后可由群主或管理员继续邀请好友；普通成员不能直接拉人。

## 3. 我的会话列表

```http
GET /api/v1/conversations
```

```json
{
  "conversations": [
    {
      "id": "1839281749283749120",
      "conversation_type": 1,
      "name": "",
      "title": "成员北辰",
      "peer_user_id": "1839281749283749121",
      "avatar_url": "",
      "last_seq": 5,
      "last_read_seq": 2,
      "unread_count": 3,
      "member_count": 3
    }
  ]
}
```

`title` 是可直接展示的业务标题：群聊使用群名称，私聊使用对方昵称或用户名。客户端不得使用内部 Snowflake ID 拼接用户可见标题。

当前只返回有效成员关系中的正常会话，按会话最近更新时间倒序，首版限制 100 条。未读数由 `last_seq - last_read_seq` 计算，结果不会是负数。

## 4. 查询会话成员

```http
GET /api/v1/conversations/:conversation_id/members
```

只有当前会话有效成员可以查询。群主按角色排在前面，其他成员按昵称和用户名排序。

```json
{
  "members": [
    {
      "user_id": "1839281749283749120",
      "username": "owner",
      "nickname": "群主阿岚",
      "avatar_url": "",
      "role": 3,
      "joined_at": "2026-11-08T02:52:35Z"
    },
    {
      "user_id": "1839281749283749121",
      "username": "member",
      "nickname": "成员北辰",
      "avatar_url": "",
      "role": 1,
      "joined_at": "2026-11-08T02:52:35Z"
    }
  ]
}
```

角色值：`1` 普通成员、`2` 管理员、`3` 群主。非成员查询返回 `404 Not Found`，避免暴露群是否存在。

## 5. 邀请群成员

```http
POST /api/v1/conversations/:conversation_id/members
Content-Type: application/json
```

```json
{
  "member_user_ids": [
    "1839281749283749123"
  ],
  "invite_remark": "邀请参与本周接口联调"
}
```

- 只有群主或管理员可以邀请，普通成员返回 `403 Forbidden`。
- 受邀用户必须是邀请人的有效好友。
- 入群邀请备注必填且最多 200 字；待处理邀请重新发送时以最新备注为准。
- 邀请只创建待审批记录，不直接增加有效成员；已是有效成员或已有未过期邀请时保持幂等。
- 邀请默认 7 天过期；过期、拒绝或取消后的同一用户可重新邀请。
- 单群有效成员上限 500，在接收邀请加入时重新校验。

```json
{
  "invited_count": 1
}
```

## 6. 处理群邀请

查询当前用户收到的待处理邀请：

```http
GET /api/v1/group-invitations?limit=20&before_id=<游标>
```

响应包含 `invitations`、`next_cursor` 和 `has_more`。邀请项包含群名称、邀请人、邀请备注、创建时间和失效时间，不暴露内部成员关系。

接受或拒绝：

```http
POST /api/v1/group-invitations/:invitation_id/accept
POST /api/v1/group-invitations/:invitation_id/reject
```

- 只有被邀请人可以处理。
- 接受时锁定邀请和群会话，重新检查邀请有效期、群状态、群人数以及是否已是成员。
- 并发重复接受保持幂等，只创建一条有效成员记录。
- 拒绝后不加入群聊，邀请记录保留用于审计。
- 群已解散、邀请过期或已经处理时返回 `409 Conflict`。

群主和管理员可以查询待处理邀请：

```http
GET /api/v1/conversations/:conversation_id/invitations
```

## 7. 移除成员与退出群聊

```http
DELETE /api/v1/conversations/:conversation_id/members/:user_id
```

- 群主可以移除普通成员或管理员。
- 管理员只能移除普通成员。
- 普通成员可以用自己的 `user_id` 调用该接口主动退群。
- 群主不能直接退群，必须先完成群主转让或解散群。
- 成功返回 `204 No Content`。

成员移除采用 `left_at` 软退出。退出后不能再发送、读取历史或访问该群附件；重新受邀后可再次加入当前群。

## 8. 设置或取消群管理员

```http
PUT /api/v1/conversations/:conversation_id/members/:user_id/role
Content-Type: application/json
```

```json
{
  "role": 2
}
```

- 只有群主可以调用该接口。
- `role=2` 设置管理员，`role=1` 取消管理员。
- 目标用户必须是当前有效成员，且不能是群主本人。
- 群主角色只能通过“转让群主”改变，不能使用该接口降级。
- 成功返回 `204 No Content`，相同角色重复设置保持幂等。

## 9. 转让群主与解散群

转让群主：

```http
POST /api/v1/conversations/:conversation_id/transfer-owner
Content-Type: application/json

{"user_id":"1839281749283749121"}
```

- 只有当前群主可以转让，受让人必须是有效成员。
- 会话 `owner_id`、新群主角色和原群主角色在同一事务中更新。
- 成功后原群主变为普通成员，新群主角色为 `3`，接口返回 `204 No Content`。

解散群：

```http
POST /api/v1/conversations/:conversation_id/dissolve
```

- 只有当前群主可以解散。
- 会话状态从 `1` 改为 `3`，成员和消息记录保留用于审计。
- 解散后会话从个人列表隐藏，成员查询、邀请成员、历史消息、已读状态和送达统计均返回“会话不存在或无权访问”。
- 成功返回 `204 No Content`。

## 10. 修改群资料

```http
PUT /api/v1/conversations/:conversation_id/profile
Content-Type: application/json
```

```json
{
  "name": "新的群名称",
  "avatar_url": "https://example.com/group.png"
}
```

- 只有当前群主可以修改，管理员和普通成员返回 `403 Forbidden`。
- 群名称去除首尾空格后不能为空，最多 64 个 Unicode 字符。
- 群头像只允许 `http` 或 `https` 地址，最多 512 字节；空字符串表示清除头像。
- 成功后返回群会话 ID、新名称和新头像。

## 11. 群聊消息

群聊文本、图片和文件继续使用统一的会话消息接口。消息可访问范围来自 `conversation_members` 中 `left_at IS NULL` 的有效成员：

- 在线成员通过 RabbitMQ Consumer 和 WebSocket 收到实时事件。
- 不在线成员重连后先获取最新页，历史由客户端使用 `before_seq` 加载。
- 已读状态按成员 `last_read_seq` 分别维护，不共享单一群状态。

## 12. 代码边界

| 文件 | 职责 |
| --- | --- |
| `internal/conversation/handler.go` | HTTP 参数转换和错误映射 |
| `internal/conversation/service.go` | 群成员输入规则、状态语义和未读数计算 |
| `internal/conversation/repository.go` | 好友校验、会话事务、邀请状态机、成员查询和唯一冲突恢复 |
| `internal/router/conversation/conversation_router.go` | 路由组装和统一认证中间件 |

当前事实来源是 `conversations`、`conversation_members`、`group_invitations` 和 `messages`。
