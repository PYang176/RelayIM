# RelayIM 演示指南

本文用于准备 GitHub 项目截图、功能演示短视频和现场演示。截图与视频应展示真实操作和已实现功能，不使用未经验证的容量数字。

## 1. 演示前准备

### 1.1 启动环境

启动前确认宿主机 MySQL 8 已运行，`deploy/app.env` 中的 `RELAYIM_MYSQL_HOST=host.docker.internal`、端口和密码指向本机数据库。

```powershell
docker compose `
  --env-file deploy\.env `
  --env-file deploy\app.env `
  -f deploy\docker-compose.yml `
  -f deploy\docker-compose.app.yml `
  up -d --build --remove-orphans
```

确认以下地址可访问：

- Web：`http://localhost:8080`
- API：`http://localhost:8081/health/ready`
- Grafana：`http://localhost:3000`
- RabbitMQ：`http://localhost:15672`
- Prometheus：`http://localhost:9090`

### 1.2 准备演示数据

```powershell
.\scripts\seed-demo.ps1
```

脚本会输出本次账号、昵称和统一密码。使用两个独立的浏览器窗口或无痕窗口分别登录两个账号，便于演示实时消息、好友申请和群邀请审批。

### 1.3 录制规范

- 浏览器缩放保持 100%，推荐 1440×900 或 1920×1080。
- 隐藏密码、Token、Cookie、邮箱和真实个人信息。
- 演示前固定数据，避免录制过程中等待随机账号注册。
- 鼠标移动简洁，点击后停留 0.5 至 1 秒，给观众留出阅读时间。
- 一次录制只演示一条主线，失败片段不要剪进最终视频。
- 容量截图必须同时保留场景、数字和已知限制。

## 3. 五分钟演示视频

### 3.1 分镜

| 时间 | 画面 | 讲解重点 |
| --- | --- | --- |
| 0:00–0:20 | 项目名称和登录页 | RelayIM 是支持文字、图片、文件、好友和群聊的即时通讯项目 |
| 0:20–0:50 | 双窗口登录两个账号 | 展示独立账号、在线状态和 WebSocket 连接 |
| 0:50–1:30 | 搜索用户、填写理由、发送并审批好友申请 | 好友申请不是直接建立关系，需对方确认 |
| 1:30–2:05 | 私聊文字、图片和文件 | 两个窗口实时显示；展示图片放大和文件下载 |
| 2:05–2:50 | 创建群、邀请成员、填写邀请备注、接受邀请 | 展示群主、管理员、成员权限和实时邀请通知 |
| 2:50–3:25 | 群成员资料、单独私聊、拉黑、删除好友 | 展示联系人关系和群成员操作闭环 |
| 3:25–3:55 | 会话搜索、置顶、历史消息搜索、撤回和已读 | 展示会话管理与历史检索 |
| 3:55–4:30 | Grafana、RabbitMQ、Outbox 和健康检查 | 讲解 MySQL 事务、Outbox、RabbitMQ Confirm 和 WebSocket 背压 |
| 4:30–5:00 | 性能验收页和架构图 | 说明 5,000 空闲连接、30 分钟长稳和 300 人同群突发结果 |

### 3.2 讲解节奏

前半段以实际操作展示产品，后半段只讲最关键的工程实现：

- 消息和 Outbox 在同一 MySQL 事务中提交。
- RabbitMQ 使用 Publisher Confirm、手动 ACK、重试队列和 DLQ。
- WebSocket 使用一次性 Ticket、有界发送队列和单写协程。
- 消息按会话 `seq` 排序，断线后通过 `after_seq` 补拉。
- 容量数字必须同时说明测试口径，例如“300 人同秒各发一条”不是“300 条/秒持续吞吐”。

## 4. 八分钟技术演示

需要深入展示工程能力时，在五分钟版本后增加：

1. `docs/需求文档.md` 的架构与消息可靠性决策。

6. 代码中的事务边界、限流、超时和优雅退出。

不要逐页朗读文档。每页只讲一个设计问题、选择方案和验证结果。

## 5. 演示数据与安全

- 演示结束后停止压测脚本，避免测试用户继续产生消息。
- 不上传真实密码、Token、Cookie、数据库数据文件或完整环境变量文件。
- 截图中的测试账号使用固定演示前缀。
- GitHub 仓库保留截图和说明；视频文件建议上传 GitHub Release 或外部视频平台后链接，避免仓库体积过大。
