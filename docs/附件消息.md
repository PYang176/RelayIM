# 附件消息

本文说明 GinChat 当前图片和文件消息的上传、权限、绑定和访问链路。

## 1. 当前范围

- 支持文本、图片和普通文件消息。
- 单个附件最大 25 MB。
- 图片在聊天记录中显示预览，文件显示下载卡片。
- 文件本体保存在 SeaweedFS 的 S3 兼容接口中，MySQL 只保存附件元数据。
- 附件默认私有，客户端通过 15 分钟有效的预签名地址访问。
- 一个附件最多绑定一条消息。

当前不包含断点续传、秒传、病毒扫描、图片压缩和未绑定附件定时清理。

## 2. 消息类型

| 值 | 类型 | 要求 |
| --- | --- | --- |
| `1` | 文本 | `content` 去空白后不能为空，不能携带附件 |
| `2` | 图片 | 必须携带附件，服务端检测到的 MIME 必须以 `image/` 开头 |
| `3` | 文件 | 必须携带附件，`content` 可选 |

服务端没有根据用户声明的扩展名决定 MIME。上传 Handler 使用文件前 512 字节调用 `http.DetectContentType`，并把检测结果写入 `attachments.mime_type`。

HTML 和 SVG 不进入允许的聊天附件链路。其他未知二进制类型按普通文件处理，下载时使用服务端检测到的 MIME，而不是浏览器上传时提交的类型。

## 3. 上传流程

### 3.1 上传附件

```http
POST /api/v1/attachments
Authorization: Bearer <JWT>
Content-Type: multipart/form-data
```

表单字段：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `file` | 文件 | 必填，最大 25 MB |

成功返回 `201 Created`：

```json
{
  "attachment_id": "2119133185785729024",
  "message_type": 2,
  "mime_type": "image/png",
  "size_bytes": 34567,
  "filename": "截图.png",
  "url": "http://127.0.0.1:8333/ginchat-media/..."
}
```

服务端执行顺序：

1. 从认证上下文读取上传者，忽略客户端伪造的 `owner_id`。
2. 限制整个 multipart 请求体大小。
3. 读取文件头部检测 MIME。
4. 生成附件 Snowflake ID 和对象键 `users/<用户ID>/attachments/<附件ID><扩展名>`。
5. 先在 MySQL 写入 `status=1` 的待确认元数据。
6. 上传对象到 SeaweedFS。
7. 把附件状态改为 `status=2` 并写入 `finalized_at`。
8. 生成短时预签名 URL 并返回。

第 6 至第 8 步失败时会尽力删除对象和元数据，避免把客户端永远拿不到 ID 的附件留在系统里。进程崩溃仍可能留下孤儿数据，后续应由定时巡检任务处理。

### 3.2 发送附件消息

图片或文件消息继续使用统一消息接口：

```http
POST /api/v1/conversations/:conversation_id/messages
Authorization: Bearer <JWT>
Content-Type: application/json
```

图片消息示例：

```json
{
  "client_message_id": "25f0f4d9-68d6-4b63-8922-6c9357612dcc",
  "message_type": 2,
  "attachment_id": "2119133185785729024",
  "content": ""
}
```

文件消息可以带一句说明：

```json
{
  "client_message_id": "4b1bde30-4902-4112-81c8-f8a8f982b890",
  "message_type": 3,
  "attachment_id": "2119133185785729024",
  "content": "这是本周的接口文档"
}
```

发送事务会验证：

- 发送者仍是会话有效成员。
- 附件属于发送者且状态为可用。
- 图片消息的附件 MIME 是 `image/*`。
- 附件尚未绑定其他消息。

消息、`last_seq`、附件绑定和 Outbox 事件在同一个 MySQL 事务中提交。`messages.attachment_id` 的唯一索引负责兜底并发绑定，不能只依赖 Go 层的“先查询再写入”。

## 4. 访问附件

### 4.1 获取新的预签名地址

```http
GET /api/v1/attachments/:id
Authorization: Bearer <JWT>
```

上传者可以访问自己的可用附件。其他用户只有在附件已经绑定到自己仍是有效成员的会话消息时才能访问。

### 4.2 受保护内容流

```http
GET /api/v1/attachments/:id/content
Authorization: Bearer <JWT>
```

该接口需要 Bearer Token，适合前端需要统一权限处理或预签名地址失效时重新拉取。图片使用 `Content-Disposition: inline`，普通文件使用 `attachment`。

前端正常展示优先使用短时预签名 URL，避免让大文件长期占用 Go HTTP 连接。

## 5. 历史消息与实时消息

历史消息中的图片或文件会返回：

```json
{
  "message_id": "2119133187215470592",
  "message_type": 2,
  "content": "",
  "attachment_id": "2119133185785729024",
  "attachment_name": "截图.png",
  "attachment_url": "http://127.0.0.1:8333/ginchat-media/..."
}
```

`attachment_url` 是短时地址，不能写入数据库或作为永久链接分享。

WebSocket 实时事件会携带受保护的内容路径：

```json
{
  "action": "message",
  "message_id": "2119133187215470592",
  "conversation_id": "2119133186507149312",
  "sender_id": "2119133185785729024",
  "seq": 3,
  "msg_type": 2,
  "content": "",
  "url": "/api/v1/attachments/2119133185785729024/content",
  "file_name": "截图.png"
}
```

前端收到受保护路径后调用 `GET /api/v1/attachments/:id` 换取新的短时预签名 URL。WebSocket 不直接广播永久对象地址。

## 6. 数据状态

`attachments.status` 的有效值：

| 值 | 名称 | 说明 |
| --- | --- | --- |
| `1` | 待确认 | 元数据已写入，对象上传尚未完成 |
| `2` | 可用 | 对象上传完成，可绑定消息 |
| `3` | 已阻止 | 风控或内容治理禁止访问 |
| `4` | 已删除 | 逻辑删除，等待物理清理 |

当前上传成功只写入 `1` 和 `2`。`3`、`4` 为后续内容治理和删除任务保留。

## 7. 本地配置

应用配置使用以下环境变量，不读取 `deploy/.env`：

```env
GINCHAT_S3_ENDPOINT=127.0.0.1:8333
GINCHAT_S3_ACCESS_KEY=<SeaweedFS 访问密钥>
GINCHAT_S3_SECRET_KEY=<SeaweedFS 秘密>
GINCHAT_S3_BUCKET=ginchat-media
GINCHAT_S3_REGION=us-east-1
GINCHAT_S3_USE_SSL=false
```

`GINCHAT_S3_ACCESS_KEY` 和 `GINCHAT_S3_SECRET_KEY` 对应 `deploy/.env` 中的 `MINIO_ROOT_USER` 和 `MINIO_ROOT_PASSWORD`。不要把真实值写进 `.env.example`、日志或接口响应。

未配置访问密钥时，应用仍可启动文本和好友等功能，但附件上传返回存储不可用。

## 8. 验证

单元测试：

```powershell
go test ./...
```

连接真实 MySQL、RabbitMQ、Redis 和 SeaweedFS 的集成测试需要显式设置测试环境变量。对象存储测试使用：

```powershell
$env:GINCHAT_TEST_S3_ENDPOINT = "127.0.0.1:8333"
$env:GINCHAT_TEST_S3_ACCESS_KEY = "<测试访问密钥>"
$env:GINCHAT_TEST_S3_SECRET_KEY = "<测试秘密>"
go test ./internal/platform/objectstore -run TestObjectStorageIntegration -v
```

浏览器验收重点：

1. 上传 PNG 后立即显示图片。
2. 上传 TXT 后显示文件卡片并可下载。
3. 刷新页面后从历史消息恢复图片和文件。
4. 非会话成员直接访问附件返回 `404`。
5. 同一附件绑定第二条消息返回 `409 Conflict`。
