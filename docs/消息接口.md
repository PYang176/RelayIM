# 消息接口

新版消息接口使用 `/api/v1` 路径和统一 Bearer 认证。发送者身份只能来自认证上下文，客户端传入 `sender_id` 不会生效。

发送消息按登录用户限流，规则见 [接口限流](./接口限流.md)。

## 1. 发送文本消息

```http
POST /api/v1/conversations/:conversation_id/messages
Authorization: Bearer <JWT>
Content-Type: application/json
```

```json
{
  "client_message_id": "b7c2d4a0-4e1e-4a7d-9c48-01",
  "content": "你好，今晚一起联调吗？",
  "reply_to_message_id": "1839281749283749120"
}
```

- `client_message_id` 必填，由客户端生成，同一发送者内最多 64 字节。
- `content` 去除首尾空白后不能为空，最多 8,000 个 Unicode 字符。
- `reply_to_message_id` 可选，必须是被引用消息的 Snowflake ID 字符串，且该消息属于当前会话。
- 首次成功创建返回 `201 Created`。
- 相同 `client_message_id` 重试返回原消息和 `200 OK`，不会重复写库或重复分配 `seq`。

成功响应：

```json
{
  "message_id": "1839281749283749121",
  "conversation_id": "1839281749283749120",
  "seq": 7,
  "created_at": "2026-11-07T08:30:00Z",
  "duplicate": false
}
```

## 2. 查询历史消息

```http
GET /api/v1/conversations/:conversation_id/messages?after_seq=10&limit=20
Authorization: Bearer <JWT>
```

查询参数：

- `after_seq`：返回序号大于该值的消息，按 `seq` 升序，用于断线补拉。
- `before_seq`：返回序号小于该值的最近一页消息，用于向前翻页。
- `after_seq` 和 `before_seq` 不能同时使用。
- `limit`：默认 20，最大 100。
- 不传游标时返回最近一页消息。

响应：

```json
{
  "messages": [
    {
      "message_id": "1839281749283749121",
      "conversation_id": "1839281749283749120",
      "sender_id": "1839281749283749001",
      "seq": 11,
      "message_type": 1,
      "content": "你好",
      "recalled": false,
      "created_at": "2026-11-07T08:30:00Z"
    }
  ],
  "has_more": true
}
```

所有结果始终按 `seq` 升序返回。只有当前会话有效成员可以查询；非成员返回 `403`。

消息同步采用“最新优先”：会话首次打开或断线重连时，客户端先请求不带游标的最新页，再从该页最早序号继续使用 `before_seq` 向上加载历史。服务端不保存设备级历史浏览位置，也不在重连时通过 WebSocket 补送全部离线消息。

当前实时窗口出现乱序或缺号时，客户端才从最后一个连续 `seq` 调用 `after_seq` 分页补齐。不能因为先收到较大的 `seq` 就把已读游标推进到该值；补拉和晚到实时帧都必须以 `message_id` 去重。服务端 `last_seq` 大于本地连续水位时，活跃会话应继续向会话末尾方向补拉。

## 3. 搜索会话内消息

```http
GET /api/v1/conversations/:conversation_id/messages/search?q=并发&limit=20
Authorization: Bearer <JWT>
```

查询参数：

- `q` 必填，去除首尾空白后为 2 到 64 个 Unicode 字符。
- `before_seq` 可选，返回消息序号小于该值的更多搜索结果。
- `limit` 默认 20，最大 100。

响应：

```json
{
  "messages": [
    {
      "message_id": "1839281749283749121",
      "conversation_id": "1839281749283749120",
      "sender_id": "1839281749283749001",
      "sender_name": "成员北辰",
      "seq": 11,
      "content": "并发消息发送成功",
      "created_at": "2026-11-07T08:30:00Z"
    }
  ],
  "next_before_seq": 11,
  "has_more": true
}
```

- 搜索范围只限当前会话，不跨会话检索。
- 只有会话有效成员可以搜索；非成员返回 `403`。
- 使用 MySQL `FULLTEXT ... WITH PARSER ngram` 支持中文，按 `seq` 倒序返回。
- 已撤回消息不进入搜索结果；图片和文件名不做正文搜索。
- 前端“聊天记录”面板默认展示最近消息，输入至少 2 个字符后切换为搜索结果。
- 搜索接口按登录用户限流：每人每分钟 30 次，全局每分钟 300 次。

## 4. 发送图片或文件消息

图片和文件先通过 `POST /api/v1/attachments` 上传，再使用同一消息接口发送：

```json
{
  "client_message_id": "25f0f4d9-68d6-4b63-8922-6c9357612dcc",
  "message_type": 2,
  "attachment_id": "2119133185785729024",
  "content": ""
}
```

- `message_type=2` 表示图片，附件 MIME 必须是 `image/*`。
- `message_type=3` 表示文件，`content` 可以是空字符串或最多 8,000 字符说明。
- 附件必须属于发送者、状态可用且尚未绑定其他消息。
- 上传大小、MIME 检测和访问权限见 [附件消息](./附件消息.md)。

历史消息会额外返回 `attachment_id`、`attachment_name` 和短时 `attachment_url`。预签名地址不能持久化。

## 5. 撤回消息

```http
DELETE /api/v1/conversations/:conversation_id/messages/:message_id
Authorization: Bearer <JWT>
```

- 原发送者可以撤回自己最近 2 分钟内的消息。
- 群主和管理员可以撤回群内最近 24 小时内的消息。
- 私聊中没有管理员角色，只能由原发送者在时间窗内撤回。
- 已撤回消息重复调用保持幂等，成功返回 `204 No Content`。
- 撤回事务同时写入 `outbox_events`，通过 RabbitMQ 推送到所有在线成员。

撤回后数据库保留原正文和附件关系用于审计，但历史接口只返回：

```json
{
  "message_id": "1839281749283749121",
  "conversation_id": "1839281749283749120",
  "sender_id": "1839281749283749001",
  "seq": 11,
  "message_type": 1,
  "content": "",
  "recalled": true,
  "recalled_at": "2026-11-07T08:31:00Z",
  "recalled_by": "1839281749283749001",
  "created_at": "2026-11-07T08:30:00Z"
}
```

附件消息撤回后不再返回附件 ID、文件名或签名地址；除附件所有者外，其他会话成员也不能继续通过附件接口访问。

## 6. 查询成员已读状态

```http
GET /api/v1/conversations/:conversation_id/read-states
Authorization: Bearer <JWT>
```

```json
{
  "read_states": [
    {
      "user_id": "1839281749283749001",
      "last_read_seq": 11
    }
  ]
}
```

只有会话有效成员可以查询。已读序号由 WebSocket `read` 回执单调推进。

## 7. 查询消息送达汇总

```http
GET /api/v1/conversations/:conversation_id/messages/:message_id/delivery
Authorization: Bearer <JWT>
```

```json
{
  "delivered_devices": 2,
  "delivered_users": 1
}
```

送达数量基于 `message_deliveries` 中客户端实际发送的 ACK，不把 WebSocket 入队成功误认为已送达。

## 8. 事务与顺序语义

发送消息时，Repository 在同一 MySQL 事务中完成以下操作：

1. 锁定 `conversations` 中的会话行。
2. 校验会话状态和发送者的有效成员关系。
3. 校验引用消息属于当前会话。
4. 媒体消息校验附件归属、状态、MIME 和唯一绑定。
5. 分配会话内连续递增的 `seq`。
6. 写入 `messages`。
7. 更新会话的 `last_seq` 和 `last_message_id`。
8. 写入 `outbox_events`。

接口成功返回表示消息和 Outbox 已经一起提交，而不是表示 RabbitMQ 已经投递。后续发布器会读取 Outbox 并可靠发布；客户端展示顺序始终以 `seq` 为准。

## 9. 错误响应

| 状态码 | 场景 |
| --- | --- |
| `400 Bad Request` | JSON、路径 ID、消息参数或引用消息 ID 不合法 |
| `401 Unauthorized` | 缺少有效登录身份 |
| `403 Forbidden` | 当前用户不是会话有效成员，或无权撤回目标消息 |
| `404 Not Found` | 会话、消息或附件不存在，或当前用户无权访问 |
| `409 Conflict` | 会话已关闭、超过撤回时间、幂等 ID 冲突或附件已绑定其他消息 |
| `413 Request Entity Too Large` | 原始请求体超过 1 MB |
| `503 Service Unavailable` | 对象存储未配置或暂时不可用 |
| `500 Internal Server Error` | 数据库或服务器内部错误 |
