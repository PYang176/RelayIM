# 消息接口

新版消息接口使用 `/api/v1` 路径和统一 Bearer 认证。发送者身份只能来自认证上下文，客户端传入 `sender_id` 不会生效。

## 1. 发送文本消息

```http
POST /api/v1/conversations/:conversation_id/messages
Authorization: Bearer <JWT>
Content-Type: application/json
```

```json
{
  "client_message_id": "b7c2d4a0-4e1e-4a7d-9c48-01",
  "content": "你好，今晚一起联调吗？",
  "reply_to_message_id": "1839281749283749120"
}
```

- `client_message_id` 必填，由客户端生成，同一发送者内最多 64 字节。
- `content` 去除首尾空白后不能为空，最多 8,000 个 Unicode 字符。
- `reply_to_message_id` 可选，必须是被引用消息的 Snowflake ID 字符串，且该消息属于当前会话。
- 首次成功创建返回 `201 Created`。
- 相同 `client_message_id` 重试返回原消息和 `200 OK`，不会重复写库或重复分配 `seq`。

成功响应：

```json
{
  "message_id": "1839281749283749121",
  "conversation_id": "1839281749283749120",
  "seq": 7,
  "created_at": "2026-11-07T08:30:00Z",
  "duplicate": false
}
```

## 2. 事务与顺序语义

发送消息时，Repository 在同一 MySQL 事务中完成以下操作：

1. 锁定 `conversations` 中的会话行。
2. 校验会话状态和发送者的有效成员关系。
3. 校验引用消息属于当前会话。
4. 分配会话内连续递增的 `seq`。
5. 写入 `messages`。
6. 更新会话的 `last_seq` 和 `last_message_id`。
7. 写入 `outbox_events`。

接口成功返回表示消息和 Outbox 已经一起提交，而不是表示 RabbitMQ 已经投递。后续发布器会读取 Outbox 并可靠发布；客户端展示顺序始终以 `seq` 为准。

## 3. 错误响应

| 状态码 | 场景 |
| --- | --- |
| `400 Bad Request` | JSON、路径 ID、消息参数或引用消息 ID 不合法 |
| `401 Unauthorized` | 缺少有效登录身份 |
| `403 Forbidden` | 当前用户不是会话有效成员 |
| `404 Not Found` | 会话不存在 |
| `409 Conflict` | 会话已关闭，或幂等 ID 被用于其他会话 |
| `413 Request Entity Too Large` | 原始请求体超过 1 MB |
| `500 Internal Server Error` | 数据库或服务器内部错误 |
