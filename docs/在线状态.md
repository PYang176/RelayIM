# 在线状态

在线状态按“用户 + 设备”记录。同一用户多台设备同时在线时，只要有一台设备保持 WebSocket 活跃，就显示在线。

## 1. 存储方式

每个用户对应一个 Redis ZSET：

```text
ginchat:presence:user:<user_id>
```

- Member 是设备 Snowflake ID。
- Score 是设备最近一次建立连接或 Pong 的 Unix 毫秒时间。
- 连接建立时立即写入。
- 服务端每 25 秒 Ping，客户端 Pong 后刷新当前设备 Score。
- 最近 70 秒内没有心跳的设备视为离线。
- 正常关闭连接时删除当前设备 Member，不影响同一用户的其他设备。

查询时由 Lua 原子清理过期设备并返回剩余设备数量，避免把所有设备 ID返回给客户端。

## 2. 批量查询

```http
POST /api/v1/presence/query
Authorization: Bearer <JWT>
Content-Type: application/json
```

```json
{
  "user_ids": [
    "1839281749283749120",
    "1839281749283749121"
  ]
}
```

规则：

- 单次查询 1 到 100 个去重用户。
- 用户 ID 一律使用 Snowflake 字符串。
- 普通聊天成员只能获得布尔在线状态，不暴露设备名称、IP 或最后活跃时间。

响应：

```json
{
  "presence": [
    {
      "user_id": "1839281749283749120",
      "online": true
    },
    {
      "user_id": "1839281749283749121",
      "online": false
    }
  ]
}
```

Redis 不可用时返回 `503 Service Unavailable`。在线状态属于辅助信息，前端查询失败不会阻塞聊天主链路。

## 3. 当前边界

- 状态只区分在线和离线，不包含“离开”“勿扰”等人工状态。
- 每个 Go 进程只维护本机 WebSocket 连接；Redis 保存设备和实例路由，RabbitMQ 节点队列负责跨实例实时投递。
- 实例退出时实时帧允许丢失，客户端重连后通过最新消息窗口和历史游标恢复。
- 在线状态不是消息送达证明，送达仍以 `message_deliveries` 的设备 ACK 为准。
