# 好友接口

所有接口要求 `Authorization: Bearer <JWT>`。用户对统一按较小的 `user_low_id` 和较大的 `user_high_id` 存储，数据库唯一索引负责并发兜底。

发送好友申请按登录用户限流，规则见 [接口限流](./接口限流.md)。

## 1. 搜索用户

```http
GET /api/v1/users/search?q=林
```

- 按用户名或昵称模糊搜索。
- 排除当前用户，最多返回 20 条。
- 只返回公开资料，不包含密码、IP 或账号状态。

好友头像或用户搜索结果可以调用 `GET /api/v1/users/:user_id` 读取昵称、头像和个人简介。

## 2. 查询关系状态

```http
GET /api/v1/friends/:user_id/relationship
```

返回当前用户针对目标用户可以执行的社交动作：

```json
{
  "target_user_id": "1839281749283749120",
  "can_message": false,
  "can_request": true,
  "has_pending_request": false,
  "requested_by_me": false,
  "blocked_by_me": false
}
```

- `can_message=true` 表示双方好友关系有效且不存在拉黑，可以直接发起私聊。
- `can_request=true` 表示当前可以发送新的好友申请。
- 已有待处理申请时 `can_request=false`，客户端通过 `requested_by_me` 区分申请方向。
- 任一方向存在拉黑时不能继续申请；接口只向当前用户返回其主动拉黑状态。
- 关系状态用于联系人资料和群成员资料中的动作按钮，不能通过分页好友缓存推断。

## 3. 发送好友申请

```http
POST /api/v1/friend-requests
```

```json
{
  "target_user_id": "1839281749283749120",
  "remark": "一起联调"
}
```

- 不能添加自己。
- `remark` 必填，去除首尾空白后不能为空，最多 200 个字符。
- 已是好友返回 `409 Conflict`。
- 双方已有待处理申请返回 `409 Conflict`。
- 已拒绝或删除后的用户对重新申请时，复用原申请行并恢复为待处理状态。

## 4. 申请列表

```http
GET /api/v1/friend-requests/received?limit=20&before_id=<游标>
GET /api/v1/friend-requests/sent?limit=20&before_id=<游标>
```

收到列表只包含待处理申请；发出列表包含待处理、已同意、已拒绝等状态。

- `limit` 默认 20，最大 100。
- `before_id` 使用上一页返回的 `next_cursor`，不传时读取第一页。
- 响应包含 `requests`、`next_cursor` 和 `has_more`。
- 列表按申请 Snowflake ID 倒序，游标分页不会因新增申请产生页码偏移。

## 5. 处理申请

```http
POST /api/v1/friend-requests/:id/accept
POST /api/v1/friend-requests/:id/reject
```

同意操作在同一事务中更新申请状态并创建或恢复 `friendships`。只有申请接收者可以处理，申请发起者调用返回 `403 Forbidden`。

## 6. 好友列表与备注

```http
GET /api/v1/friends?limit=20&before_id=<游标>
PUT /api/v1/friends/:user_id/remark
DELETE /api/v1/friends/:user_id
```

备注请求：

```json
{
  "remark": "产品-周屿"
}
```

- 双方备注相互独立，保存在 `friend_remarks(friendship_id, user_id)`。
- 空备注表示删除自己的备注，不影响对方。
- 删除好友是单向操作：删除方联系人中不再显示对方，对方仍保留该联系人。
- 任意一方删除好友后，双方都不能继续发送私聊，历史会话仍可查看。
- 删除方自己的备注会被清理，另一方的备注保持不变。
- 再次发送申请并由对方接受后，双方关系恢复。
- 好友列表按关系 Snowflake ID 倒序，响应包含 `friends`、`next_cursor` 和 `has_more`。
- `relationship_active=false` 表示对方已单向删除当前用户，联系人仍在但不能再发起私聊。

## 7. 拉黑与取消拉黑

```http
GET /api/v1/user-blocks?limit=20&before_id=<游标>
POST /api/v1/users/:user_id/block
DELETE /api/v1/users/:user_id/block
```

- 拉黑关系有方向，记录在 `user_blocks(blocker_id, blocked_id)`。
- 任一方向存在拉黑时，双方都不能发送好友申请或继续发送私聊消息。
- 历史消息和会话仍然可读，群聊消息不受私聊拉黑影响。
- 同一用户重复拉黑保持幂等，取消不存在的关系也保持幂等。
- 好友列表通过 `blocked_by_me` 标识当前用户主动拉黑的好友。
- 拉黑列表只返回当前用户主动拉黑的用户，用于取消拉黑。
- 拉黑列表按被拉黑用户 Snowflake ID 倒序，响应包含 `blocked_users`、`next_cursor` 和 `has_more`。

## 8. 前端入口

左侧功能栏“联系人”切换到联系人工作区：

- 独立“添加好友”入口，进入后再搜索用户和填写申请理由。
- 收到/发出申请。
- 同意与拒绝。
- 好友列表只用于选择联系人，双击有效好友可直接打开私聊。
- 点击好友后，右侧显示资料、放大头像、发私聊和添加到群聊操作。
- 好友备注在右侧资料页就地编辑，空备注表示清除。
- 被对方单向删除后，联系人资料页提供“申请添加好友”入口。
- 拉黑、取消拉黑和单向删除集中在右侧资料页，拉黑与删除需要二次确认。
- 左侧可以查看当前拉黑列表。

群聊成员入口对所有群成员开放：

- 顶部成员条和“群成员列表”都可以打开成员资料。
- 成员资料展示头像、昵称、账号、个人简介和好友关系状态。
- 已是好友时显示“发私聊”；尚不是好友、关系已失效或尚未建立关系时显示“申请添加好友”。
- 好友申请必须填写理由，已有待处理申请时显示申请方向和等待状态。
