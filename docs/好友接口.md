# 好友接口

所有接口要求 `Authorization: Bearer <JWT>`。用户对统一按较小的 `user_low_id` 和较大的 `user_high_id` 存储，数据库唯一索引负责并发兜底。

发送好友申请按登录用户限流，规则见 [接口限流](./接口限流.md)。

## 1. 搜索用户

```http
GET /api/v1/users/search?q=林
```

- 按用户名或昵称模糊搜索。
- 排除当前用户，最多返回 20 条。
- 只返回公开资料，不包含密码、IP 或账号状态。

## 2. 发送好友申请

```http
POST /api/v1/friend-requests
```

```json
{
  "target_user_id": "1839281749283749120",
  "remark": "一起联调"
}
```

- 不能添加自己。
- `remark` 必填，去除首尾空白后不能为空，最多 200 个字符。
- 已是好友返回 `409 Conflict`。
- 双方已有待处理申请返回 `409 Conflict`。
- 已拒绝或删除后的用户对重新申请时，复用原申请行并恢复为待处理状态。

## 3. 申请列表

```http
GET /api/v1/friend-requests/received
GET /api/v1/friend-requests/sent
```

收到列表只包含待处理申请；发出列表包含待处理、已同意、已拒绝等状态。

## 4. 处理申请

```http
POST /api/v1/friend-requests/:id/accept
POST /api/v1/friend-requests/:id/reject
```

同意操作在同一事务中更新申请状态并创建或恢复 `friendships`。只有申请接收者可以处理，申请发起者调用返回 `403 Forbidden`。

## 5. 好友列表与备注

```http
GET /api/v1/friends
PUT /api/v1/friends/:user_id/remark
DELETE /api/v1/friends/:user_id
```

备注请求：

```json
{
  "remark": "产品-周屿"
}
```

- 双方备注相互独立，保存在 `friend_remarks(friendship_id, user_id)`。
- 空备注表示删除自己的备注，不影响对方。
- 删除好友为软删除；再次同意申请时恢复原关系行。

## 6. 拉黑与取消拉黑

```http
GET /api/v1/user-blocks
POST /api/v1/users/:user_id/block
DELETE /api/v1/users/:user_id/block
```

- 拉黑关系有方向，记录在 `user_blocks(blocker_id, blocked_id)`。
- 任一方向存在拉黑时，双方都不能发送好友申请或继续发送私聊消息。
- 历史消息和会话仍然可读，群聊消息不受私聊拉黑影响。
- 同一用户重复拉黑保持幂等，取消不存在的关系也保持幂等。
- 好友列表通过 `blocked_by_me` 标识当前用户主动拉黑的好友。
- 拉黑列表只返回当前用户主动拉黑的用户，用于取消拉黑。

## 7. 前端入口

聊天页右上角“好友”按钮打开联系人抽屉：

- 用户搜索与申请。
- 收到/发出申请。
- 同意与拒绝。
- 好友备注、删除和直接打开私聊。
- 拉黑、取消拉黑和查看当前拉黑列表。
